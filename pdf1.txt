L’ECOSYSTEME HADOOP 1 APACHE HADOOP: DEFINITION
C’est un framework Big Data qui permet de faire des calculs distribués sur un très grand
volume de données sur plusieurs machines
Son écosystème est constitué d’un ensemble de composants permettant de répondre à
diverses problématiques notamment le machine learning, l’analyse de données et
l’automatisation des traitements 
Il facilite la scalabilité horizontale et verticale des traitements  
Il s’appuie sur une technique de parallélisme de traitements   
Il offre un service de haute disponibilité et une tolérance aux pannes 
Il peut se connecter à plusieurs sources de données et est compatible avec JAVA
nativement et avec  R, PYTHON et SCALA grace à des librairiesAPACHE HADOOP: DEFINITIONLES CŒURS D’HADOOP (1ERE PARTIE): 
HDFS   
HFDS (Hadoop File Distributed System) est un système de stockage distribué qui permet à Hadoop
de lire des données en entrée et de les stocker en sortie
HDFS repose sur deux serveurs (encore appelés <daemons>): 
Le Namenode: il stocke les informations relatives aux propriétés  de distribution des données .
Pour un fichier qui s’appelle <users> dans un répertoire  <raw> (découpé en  mémoire en 20 blocs
)  et distribué sur 4 machines , il sait où se trouve chaque bloc. Le namenode est unique.
Le Datanode: Son rôle est de stocker les blocs de données. Pour une machine, il y a un datanode.
Il est en constante communication avec le Namenode pour recevoir les données et envoyer à ce
dernier les informations relatives à leur stockageLES CŒURS D’HADOOP (1ERE PARTIE):

YARN   
YARN (Yet Another Resource Negotiator) est le gestionnaire de ressources d’Hadoop. . Il fournit
une base sûre et stable pour la gestion opérationnelle et le partage des ressources du système, pour
une efficacité et une flexibilité maximale.
Son rôle:
Il alloue des ressources pour chaque traitement
Il surveille les traitements exécutés dans les différentes machines
Il coordonne l’éxecution des applications de façon distribuéeLES CŒURS D’HADOOP (3EME PARTIE): 
YARN   
Yarn est composé de 6 composants:
Ressource Manager: C’est lui qui reçoit les instructions d’exécution des jobs (job = rogramme à
exécuter ) à l’entrée, alloue les ressources et programme leur exécution
Scheduler:  C’est un composant du RM. Il programme les exécutions des jobs en fonction des
ressources disponibles et de la demande des applications
ApplicationManager: C’est le compoant du RM qui reçoit les jobs et négocie la création des
conteneurs dans un noeud chez le RessourceManager
ApplicationMaster: Contenu dans chaque noeud et associé à une application unique, .il supervise
l’exécution du job de façon distribuée,. Il produit également les logs applicatifs asociés LES CŒURS D’HADOOP (3EME PARTIE): 
YARN   
NodeManager: Il surveille les exécutions dans chaque noeud (une machine en réseau dans le
cluster) où il se trouve (1 noeud = 1 NodeManager) et rapporte les données au Ressource
Manager. Somme toute, il assure le monitoring  d’infrastructure du Node (RAM, CPU, Statut de
santé des nodes, etc...) 
Container: Ils sont contrôlés par les NodeManagers. Ils contiennent les ressources physiques
nécessaires pour l’exécution des jobs (RAM, CPU, espace disque) sur un node.PROCESSUS DE YARN  PROCESSUS DE YARN  
1- Un job (un traitement) est soumis à l’écosystème Hadoop. Le gestionnaire de ressources
d’Hadoop (Yarn) s’active et envoie le besoin au Ressource Manager
2- Le RM crée un conteneur pour démarrer l’Application Manager 
3- L’AM s’enregistre chez le RM 
4- L’AM négocie les ressources nécessaires pour l’exécution du job (les conteneurs nécessaires)
5- L’AM demande au NodeManager de créer les conteneurs dans lesquesls seront exécutés les
traitements
6- Les conteneurs exécutent le job de façon distribuée
7- Le client peut demander les métriques de suivi des traitements grace au RM
8- Le gestionnaire d’applications se désinscrit du RM et la mémoire est libérée pour d’autres jobsHADOOP AVEC SQL: HIVE HADOOP AVEC SQL: HIVE

Les Resilient Distributed Dataset sont des collections immuables d’objets qui effectuent des
calculs sur plusieurs nods d’un cluster. Les RDDs constitue la structure de données
fondamentale de SPARK.
L’acronyme RDD:
Resilient:  Les RDDs offrent une tolérance à la panne grace à l’aide son système de Data
Lineage avec des DAGs (prochain chapitre).
Distributed: Les Datasets  sont sur plusieurs noeuds d’un cluster
Datasets:  Ce sont des enregistrements de données avec lesquels nous travaillons
Les RDD sont automatiquement partitionnés sur plusieurs serveurs et peuvent être traités sur
plusieurs noeuds d’un clusterLES CARACTERISTIQUES DES RDD
Les RDDs sont stockés en mémoire RAM pour des
traitements plus rapides
Les opérations sont dit “paresseuses” ce qui veut
qui dire qu’elles ne sont exécutées que si elles sont
nécessaires (par contre elles sont chargées en
mémoire)
Il y a la tolérance aux pannes
Les objets sont immuables: quand ils sont écrits en
mémoire on ne peut plus les modifier LES CARACTERISTIQUES DES RDD
Les données sont distribuées sur plusieurs noeuds
pour faciliter le parallélisme des traitements 
Les données peuvent être persistées aussi bien en
mémoire que sur disque
Les RDDs peuvent être partitionnés rendant très
flexible la distribution des données sur les nodes et
sur le parallélisme
Les RDD prennent charge 2 types d’opérations: Les
transformations et les ActionsLES RDD: 
TRANSFORMATIONS ET ACTIONS
Il existe 2 types d’opérations sur les RDDs.
Les transformations: Ce sont des fonctions qui ont pour objectif de créer de nouveaux
RDDs à partir d’un RDD existant ou en chargeant des données issues d’une source.
Exemple: Map(),, Filter() ou Sample()
Les actions: Ce sont des fonctions qui ont pour objectif de créer le résultat issus de
plusieurs transformations. Il produit une donnée qui n’est pas type RDD et qui est stocké
en mémoire dans le Driver. C’est également à travers ces fonctions qu’on peut exporter les
résultats vers n’importe quel support de stockage. Exemple: First(), take() et count()SPARK:
RDD, DATAFRAME ET DATASETS
Les RDD:  Ils ont utilisés pour les données non structurées ou sans schéma prédéfini
nécessitant des calculs basiques (map, filter, etc..) et les calculs de groupements..
Commande associée (Python): sc.parallelize (pour les collections ) et sc.textFile pour charger
un fichier texte..
Les Dataframes: Ils permettent de manipuler la donnée avec des opérations de type SQL. C’est
très pratique pour les traitements qui nécessitent pas une logique métier complexe. C’est l’idéal
pour manipuler les données structurées. 
Commande associée (Python):  spark.read.csv  pour charger les csv SPARK:
RDD, DATAFRAME ET DATASETS
Les Datasets: Ils permettent d’avoir le meilleur des Dataframes et des RDDs.  ils sont
recommandés pour manipuler des données fortement typés et bénéficier des avantages
associés lors de la compilation. 
Ils combinent les avantages des 2 précédentes structures de données. De façon sommaire les
Dataframes sont des datasets non typés.
Il existe des commandes pour naviguer d’une structure à une autre.
Attention: ils ne sont disponibles qu’en Java et en Scala.L’ARCHITECTURE SPARKL’ARCHITECTURE SPARK
SPARK DRIVER :   C’est le programme central qui se charge du bon fonctionnement d’une
application SPARK. Il crée un connecteur qu’on appelle le SparkContext qui a pour objectif
d’établir le lien avec les clusters Spark et de monitorer les traitements sur les données.
SPARK CONTEXT: Il établit le lien entre le SPARK DRIVER et le CLUSTER MANAGER. Il
coordonne l’exécution des tâches et il permet de créer les variables nécessaires pour manipuler
les données notamment les RDDs.
SPARK EXECUTOR: C’est un programme qui exécute les différentes tâches nécessaires pour un
traitement SPARK. Il assure les opérations de lecture/écriture sur disque. Il tourne sur un
WORKER Node.
CLUSTER MANAGER:  Il est responsable de l’allocation des ressources et la gestion du cluster. LES TYPES DE CLUSTER MANAGER
STANDALONE CLUSTER: C’est le cluster manager natif de SPARK. Il est utilisé pour les clusters de
petites et de moyennes tailles. C’est l’idéal pour les projets en développement ou pour les tests car il
contient les fonctions basiques pour manager un cluster.
YARN:  C’est le  gestionnaire de ressources de l’écosystème HADOOP. Il permet une grande
scalabilité contrairement au mode Standalone. Toutefois il nécessite une configuration complexe
pour s’interfacer avec SPARK.
MEZOS:  Il offre les même avantages que YARN à l’exception de la forte compatibilité avec
HADOOP.  Il est préconisé lorsqu’on veut une forte isolation entre les clusters (Sécurité). 
KUBERNETES: C’est un orchestrateur de conteneurs. C’est l’idéal lorsque les applications sont
déployées dans des conteneurs.  FONCTIONNEMENT INTERNE D’UN RDD:

Les Jobs:  Un job est un ensemble de transformations appliquées sur une donnée. Chaque fois
qu’une action est appelée sur un RDD, un job est crée. Un programme SPARK peut contenir
plusieurs actions et ainsi pourrait donner lieu à plusieurs jobs en cours. Un job se subdivise en
plusieurs Stages.
Les Stages:  Ce sont regroupements d’opérations  (transformations et actions) en fonction de
leur nature et leurs dépendances.  On distingue deux types de transformations. Celles qui
nécessitent une étape de Shuffling (exemple: groupByKey() ) qui sont dites “Wide” et celles
qui n’en nécessitent pas (exemple: Filter() ) qui son dites “Narrow”. A chaque transformation
nécessitant un shuffle, un nouveau Stage est crée. Un Stage est constitué de plusieurs “Task”.  FONCTIONNEMENT INTERNE D’UN RDD:

Les Tasks:  C’est la plus petite unité de travail de Spark. C’est un traitement qui est exécuté sur
une seule machine (exécuteur). Du point de vue pratique ce sont des opérations de
transformations encapsulées pour être traitées dans des exécuteurs sur une partition de données
De façon sommaire, une application Spark est subdivisée en plusieurs Jobs en fonction des
actions. Chaque Job peut être subdivisé en plusieurs Stages selon les types de transformations.
Les Stages sont subdivisés en plusieurs Tasks qui sont exécutées en parallèle par des exécuteurs.
Les exécuteurs sont des programmes qui tournent dans des Workers nodes (machines en
réseau). Les Worker nodes sont orchestrés par un Cluster Manager. FONCTIONNEMENT INTERNE D’UN RDD:

Les DAG:  Dans Apache Spark, DAG signifie Directed Acyclic Graph (graphe acyclique dirigé). Il
s'agit d'un concept fondamental utilisé par le moteur d'exécution de Spark pour représenter et
optimiser le flux d'opérations dans un travail de traitement de données.  Il peut déterminer les
dépendances et exécuter les étapes dans l'ordre le plus efficace.
En d’autres termes ce sont des séquences de transformations qui se terminent par une action.

SPARK SQL est le composant de SPARK qui permet de manipuler les données sous forme
tabulaire en s’appuyant sur SQL.
Les avantages sont les suivants:
 Facilité d’utilisation: Le SQL est accessible à tous
Optimisation dans les traitements: Spark possède un composant pour réduire l’utilisation des
ressources et améliorer la rapidité d’éxécution des requêtes
Intéropérabilité: Il permet de manipuler des données de plusieurs formats
Intégration: Il est compatible avec JAVA, R, SCALA, PYTHON

Lorsque les données sont chargées dans un DataFrame on peut créer des vues (en approche
datamart) au sein SPARK. Ces vues sont des tables HIVE. En effet  SPARK contient un
composant minimaliste (avec le moins de dépendance possible) HIVE qui permet de manipuler
des données avec une approche SQL (si vous activez Hive).
Pour manipuler les données sous format SQL il existe 2 approches:
createOrReplaceTempView: pour créer des vues temporaires qui disparaissent après la
fermeture de la session.
df.createOrReplaceTempView("employes")
saveAsTable : pour sauvegarder les tables sur le disque.
df.write.format("parquet").mode("append").saveAsTable("my_table")TECHNIQUE DE PERSISTANCE
 DES DONNEES
Dans certains il est pertinent de stocker les résultats intermédiaires des traitements dans le but
d’optimiser les performances de l’application SPARK.
On distingue 2 façons de persistance des données:
Cache:  Cette opération permet le stockage en mémoire des données
Persist: Cette opération permet le stockage sur disque des données et en mémoire en fonction
du paramètre passé à la fonction.
MEMORY_ONLY:  Stockage en mémoire
MEMORY_ONLY_SER: Stockage en mémoire désérialiser pour réduire l’espace sur disque
MEMORY_AND_DISK: Stockage en mémoire et sur disque
MEMORY_AND_DISK_SER: Stockage en mémoire et sur disque de façon désérialiséeSPARK SUBMIT
Il existe 2 modes de déploiement d’une application Spark:
Client:  le driver reste local, utile pour tester ou déboguer.
Cluster: le driver est dans le cluster YARN, plus robuste et idéal en production.
Pour soumettre une application spark la syntaxe est la suivante:
spark-submit \
  --master yarn \
  --deploy-mode cluster \
  --executor-memory 2G \
  --num-executors 2 \
  --executor-cores 2  fichier.pyPARAMETRES CLASSIQUES
--master yarn/spark/mezos/kubernetes : Mode de déploiement sur YARN
--deploy-mode cluster/client:   Où tourne le driver
--executor-memory: Mémoire pour chaque exécuteur
--num-executors: Nombre total d’exécuteurs
--executor-cores: Nombre de cœurs par exécuteur
4Go / 8 machines  => 500Mb / machine
5 blocs HDFS de fichiers pour 500mb (avec la valeur de 128 Mb de HDFS)
1Go => 1000Mb
executor memory =  Taille de chaque bloc majoré de 25% 
nombre total de mémoire possible  = taille du clusterSPARK EXAM FINAL
